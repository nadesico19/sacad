# Sacad Features

> **AI-generated documentation:** This document was generated by **OpenAI GPT-5 Codex** from the current Sacad Python source. It should be reviewed when the public API or the managed AutoCAD plug-in changes.

Sacad (Simple AutoCAD) is a Python toolbox for building and exchanging AutoCAD database objects in batches. Python code describes entities, styles, blocks, groups, and database operations as ordinary objects; Sacad serializes the request and delegates the AutoCAD-sensitive work to a managed ObjectARX plug-in. ActiveX automation is kept mainly at the application and command boundary, reducing the number of cross-process calls required for large drawings.

The features below are derived exclusively from Sacad's implementation and public object model.

## Highlights

- Batch creation and insertion of drawing entities, symbol-table records, groups, and complete in-memory databases.
- Retrieval of model-space content, selected entities, named groups, blocks, and style tables from AutoCAD.
- Deletion by entity identity or group name, including optional deletion of the entities owned by a group.
- A serializable object model suitable for exchanging drawing data across process boundaries and storing reusable JSON drawing templates.
- Two- and three-dimensional vectors plus composable translation, rotation, scaling, and mirroring matrices.
- Common drafting entities: lines, arcs, circles, ellipses, lightweight polylines, solids, text, multiline text, multileaders, hatches, shapes, block references, and dimensions.
- Drawing resources: blocks, layers, linetypes, text styles, dimension styles, multileader styles, and groups.
- AutoCAD version discovery and selection, one-shot managed sessions, application activation, and command dispatch.

## Practical feature guide

The examples in this section use generic names and data. They are intentionally small so each Sacad feature can be adapted independently.

### Discover AutoCAD and manage a session

Sacad can discover supported AutoCAD installations, target a specific version, start it when necessary, and close the Sacad session automatically. Activate AutoCAD before operations that prompt the user.

```python
import sacad as ac

versions = ac.Acad.get_available()
if not versions:
    raise RuntimeError("No supported AutoCAD installation was found.")

with ac.instant_acad(acad_name=versions[-1]) as cad:
    print("Connected to AutoCAD", cad.name)
    cad.activate()
```

### Generate entities and styles

Entities and named drawing resources are ordinary Python objects. They can be assembled in an in-memory `Database` before AutoCAD is opened. The example creates a linetype, a layer, text and dimension styles, and several entities that use those styles.

```python
import sacad as ac

db = ac.Database()

db.linetype_table["DASHED_SAMPLE"] = ac.LinetypeTableRecord(
    name="DASHED_SAMPLE",
    comments="Generated by Sacad",
    pattern_length=12.0,
    segments=[
        ac.LinetypeSegment(dash_length=8.0),
        ac.LinetypeSegment(dash_length=-4.0),
    ],
)
db.layer_table["OUTLINE"] = ac.LayerTableRecord(
    name="OUTLINE",
    color=ac.Color.index(3, ac.ColorMethod.BY_ACI),
    linetype="DASHED_SAMPLE",
    line_weight=ac.LineWeight.LINE_WEIGHT_025,
)
db.text_style_table["LABEL"] = ac.TextStyleTableRecord(
    name="LABEL",
    file_name="txt.shx",
    text_size=0.0,
    x_scale=1.0,
)
db.dim_style_table["DIM_SAMPLE"] = ac.DimStyleTableRecord(
    name="DIM_SAMPLE",
    dimscale=1.0,
    dimtxt=2.5,
    dimasz=2.5,
    dimtxsty="LABEL",
)

model_space = db.get_block(ac.MODEL_SPACE)
model_space.entities.extend([
    ac.Line.new(0, 0, 100, 0, layer="OUTLINE"),
    ac.Circle.new(50, 25, 12, layer="OUTLINE"),
    ac.Polyline.new(
        ac.Vertex.new(0, 0),
        ac.Vertex.new(100, 0),
        ac.Vertex.new(100, 50),
        ac.Vertex.new(0, 50),
        closed=True,
        layer="OUTLINE",
    ),
    ac.DBText.new(
        50, 60, "SAMPLE", ac.AttachmentPoint.MIDDLE_CENTER,
        height=5, text_style_name="LABEL",
    ),
    ac.AlignedDimension.new(
        0, 0, 100, 0, 0, -15,
        dimension_style_name="DIM_SAMPLE",
    ),
])
```

### Insert a complete drawing in one batch

`replace_db()` attaches a prepared database to an insertion operation. Styles, blocks, groups, and model-space entities are transferred together. An explicit insertion point can be supplied, or AutoCAD can prompt the user for one.

```python
import sacad as ac

with ac.instant_acad() as cad:
    operation = cad.db_insert(
        prompt_insertion_point=True,
        upsert=True,
        zoom_mode=ac.ZoomMode.ADDED,
        zoom_factor=1.25,
    )
    operation.replace_db(db)
    cad.activate()
    result = operation.submit()

print(result.status, result.num_inserted, result.num_updated)
```

For non-interactive placement, replace `prompt_insertion_point=True` with an explicit point:

```python
operation = cad.db_insert(insertion_point=ac.Vector3d(250, 100, 0))
operation.replace_db(db)
result = operation.submit()
```

### Extract and reuse entities and styles

Model-space entities and style tables can be read from the active drawing, serialized, and reused later. This supports reusable style libraries and drawing fragments without requiring a live AutoCAD session while the saved data is being processed.

```python
from pathlib import Path
import sacad as ac

flags = (
    ac.TableFlags.MODEL_SPACE
    | ac.TableFlags.TEXT_STYLE
    | ac.TableFlags.LINETYPE
    | ac.TableFlags.LAYER
    | ac.TableFlags.DIM_STYLE
    | ac.TableFlags.M_LEADER_STYLE
)

with ac.instant_acad() as cad:
    extracted = cad.db_get_tables(flags).submit().db

library_path = Path("drawing-library.json")
library_path.write_text(extracted.serialize(indent=2), encoding="utf-8")

reusable_db = ac.Jsonify.deserialize(
    library_path.read_text(encoding="utf-8")
)
with ac.instant_acad() as cad:
    operation = cad.db_insert(upsert=True)
    operation.replace_db(reusable_db)
    operation.submit()
```

Named blocks can be extracted separately. In the current implementation, pass the names explicitly.

```python
with ac.instant_acad() as cad:
    result = cad.db_get_tables(
        ac.TableFlags.BLOCKS,
        block_names=["SYMBOL_A", "SYMBOL_B"],
    ).submit()
    reusable_blocks = result.db.block_table
```

### Define and reuse blocks

A `BlockTableRecord` stores a named component definition. Insert a matching `BlockReference` into model space to place the component repeatedly with different positions, rotations, and scale factors.

```python
import math
import sacad as ac

db = ac.Database()
db.block_table["MARKER"] = ac.BlockTableRecord(
    name="MARKER",
    entities=[
        ac.Circle.new(0, 0, 5),
        ac.Line.new(-7, 0, 7, 0),
        ac.Line.new(0, -7, 0, 7),
    ],
)

db.get_block(ac.MODEL_SPACE).entities.extend([
    ac.BlockReference(
        name="MARKER",
        position=ac.Vector3d(20, 20, 0),
    ),
    ac.BlockReference(
        name="MARKER",
        position=ac.Vector3d(80, 20, 0),
        rotation=math.pi / 4,
        scale_factors=ac.Vector3d(2, 2, 1),
    ),
])

with ac.instant_acad() as cad:
    operation = cad.db_insert(upsert=True)
    operation.replace_db(db)
    operation.submit()
```

### Build text-replacement drawing templates

A drawing template can be stored as a serialized `Database` whose `DBText`, `MText`, or dimension text contains placeholders. Load the template, replace the placeholders, and insert the rendered database. Because styles and block definitions can live in the same database, the template is self-contained.

```python
from pathlib import Path
import sacad as ac


def replace_tokens(value, values):
    if value is None:
        return None
    for name, replacement in values.items():
        value = value.replace("<{}>".format(name), str(replacement))
    return value


template = ac.Jsonify.deserialize(
    Path("drawing-template.json").read_text(encoding="utf-8")
)
values = {
    "TITLE": "General Arrangement",
    "DRAWING_NO": "A-001",
    "REVISION": "B",
}

for block in template.block_table.values():
    for entity in block.entities:
        if isinstance(entity, ac.DBText):
            entity.text_string = replace_tokens(entity.text_string, values)
        elif isinstance(entity, ac.MText):
            entity.contents = replace_tokens(entity.contents, values)
        elif isinstance(entity, ac.Dimension):
            entity.dimension_text = replace_tokens(
                entity.dimension_text, values
            )

with ac.instant_acad() as cad:
    operation = cad.db_insert(prompt_insertion_point=True, upsert=True)
    operation.replace_db(template)
    cad.activate()
    operation.submit()
```

To create the template JSON from the active drawing, retrieve model space and the required resource tables, then serialize the returned database as shown in the previous section.

### Save the current drawing as a DWG

Sacad currently has no dedicated DWG-export database query. After submitting the drawing content, use the AutoCAD application object exposed by `Acad.com` to save the active document. An absolute `.dwg` path is recommended.

```python
from pathlib import Path
import sacad as ac

output_path = Path("output.dwg").resolve()

with ac.instant_acad() as cad:
    operation = cad.db_insert()
    operation.replace_db(db)
    operation.submit()

    document = cad.com.app.ActiveDocument
    document.SaveAs(str(output_path))
```

`SaveAs` acts on the entire active AutoCAD document. It is a document-level ActiveX operation rather than a Sacad database batch operation.

### Operate on user-selected entities

Sacad can read either the pick-first selection or a selection requested through an AutoCAD prompt. Returned entities include their AutoCAD object IDs, allowing the originals to be deleted after edited replacements have been inserted.

```python
import sacad as ac

with ac.instant_acad() as cad:
    selection = cad.db_get_user_selection(by_prompt=True)
    cad.activate()
    selected_db = selection.submit().db
    selected = selected_db.get_block(ac.MODEL_SPACE).entities

    # Change the selected text objects and insert the edited copies.
    for entity in selected:
        if isinstance(entity, ac.DBText):
            entity.text_string = entity.text_string.upper()

    insert_operation = cad.db_insert(
        insertion_point=ac.Vector3d(150, 0, 0)
    )
    insert_operation.model_space.insert_many(selected)
    insert_operation.submit()
```

Set `explode_blocks=True` when selected block references should be returned as their component entities:

```python
selection = cad.db_get_user_selection(
    by_prompt=True,
    explode_blocks=True,
)
```

### Replace existing entities safely

Insertion creates new AutoCAD objects even when the Python entities originated from a selection. To replace existing content, submit the replacements first and delete the original object IDs only after insertion succeeds.

```python
import sacad as ac

with ac.instant_acad() as cad:
    selection = cad.db_get_user_selection(by_prompt=True)
    cad.activate()
    original_db = selection.submit().db
    originals = original_db.get_block(ac.MODEL_SPACE).entities

    replacements = [entity.clone() for entity in originals]
    for entity in replacements:
        if isinstance(entity, ac.DBText):
            entity.text_string = "REPLACED"

    insertion = cad.db_insert()
    insertion.model_space.insert_many(replacements)
    insertion.submit()

    deletion = cad.db_delete()
    deletion.query.database.get_block(
        ac.MODEL_SPACE
    ).entities.extend(originals)
    deletion.submit()
```

The insert and delete calls are separate AutoCAD transactions; applications that need recovery should retain the original serialized selection until both operations complete.

### Create, retrieve, and delete entity groups

`insert_and_ref()` assigns temporary identities that allow newly inserted entities to be referenced by a `Group` in the same database request.

```python
import sacad as ac

with ac.instant_acad() as cad:
    insertion = cad.db_insert()
    first_id = insertion.model_space.insert_and_ref(
        ac.Line.new(0, 0, 100, 0)
    )
    second_id = insertion.model_space.insert_and_ref(
        ac.Line.new(100, 0, 100, 50)
    )
    insertion.query.database.group_dict["COMPONENT_A"] = ac.Group(
        name="COMPONENT_A",
        entity_ids=[first_id, second_id],
        selectable=True,
    )
    insertion.submit()

    grouped = cad.db_get_groups("COMPONENT_A").submit().db
    group = grouped.group_dict["COMPONENT_A"]
    entities = grouped.get_block(ac.MODEL_SPACE).entities
    print(group.name, len(entities))

    deletion = cad.db_delete(delete_group_entities=True)
    deletion.delete_group("COMPONENT_A")
    deletion.submit()
```

Use `delete_group_entities=False` or omit the option to remove the group while retaining its entities.

### Calculate AutoCAD-dependent entity properties

Some properties, including reliable geometric extents and adjusted text alignment, require AutoCAD. `db_test_entities()` converts candidate entities inside AutoCAD and returns the evaluated forms without inserting them into the drawing.

```python
import sacad as ac

candidates = [
    ac.DBText.new(
        0, 0, "EXTENTS TEST",
        ac.AttachmentPoint.MIDDLE_CENTER,
        height=5,
    ),
    ac.Circle.new(25, 10, 8),
]

with ac.instant_acad() as cad:
    test = cad.db_test_entities()
    test.tested_entities.insert_many(candidates)
    evaluated_db = test.submit().db

for entity in evaluated_db.get_block(ac.MODEL_SPACE).entities:
    if entity.geometric_extents is not None:
        print(
            entity.geometric_extents.min_point,
            entity.geometric_extents.max_point,
        )
```

### Transform and arrange reusable geometry

`Matrix3d` transformations can be composed and attached to any entity. This makes it possible to reuse one entity set at different scales, rotations, mirror states, and positions.

```python
import sacad as ac

source_entities = [
    ac.Line.new(0, 0, 40, 0),
    ac.Circle.new(20, 10, 5),
]

matrix = (
    ac.Matrix3d.identity()
    .scale(0.5, mirror_x=True)
    .rotate(90)
    .move(120, 80)
)

placed_entities = [entity.clone() for entity in source_entities]
for entity in placed_entities:
    entity.transform_by(matrix)

with ac.instant_acad() as cad:
    insertion = cad.db_insert()
    insertion.model_space.insert_many(placed_entities)
    insertion.submit()

```

### Serialize drawing and layout data

All Sacad database and geometry types inherit `Jsonify`. Custom dataclasses can do the same when a small serializable configuration model is useful.

```python
from dataclasses import dataclass, field
from typing import List
import sacad as ac


@dataclass
class SheetLayout(ac.Jsonify):
    name: str
    origins: List[ac.Vector2d] = field(default_factory=list)


layout = SheetLayout(
    name="SHEET-01",
    origins=[ac.Vector2d(0, 0), ac.Vector2d(420, 0)],
)
json_text = layout.serialize(indent=2)
restored = SheetLayout.deserialize(json_text)
```

Serialized custom objects contain their full module and class names. The defining module must therefore be importable wherever such an object is reconstructed. Keeping transferable drawing payloads limited to Sacad types avoids dependencies on unrelated domain packages.

## AutoCAD sessions and application control

`Acad` is the main facade for communicating with AutoCAD.

- `Acad(acad_name=..., host=..., port=...)` targets a specific supported AutoCAD release and configures the TCP callback endpoint used by the Python/managed bridge.
- `open()` connects to AutoCAD and starts an AutoCAD process when necessary. By default it also runs `NETLOAD` for the managed Sacad plug-in.
- `reset()` discards a broken connection and permits reopening; `close()` permanently closes that session object.
- `instant_acad(...)` is a context manager for one-shot scripts and automatically opens and closes the session.
- `sta=True` initializes COM as a single-threaded apartment, which is useful when submission is performed by a worker thread rather than the creating thread.
- `activate()` brings AutoCAD to the foreground before an interactive selection or insertion-point prompt.
- `send_command(name, *args)` sends an AutoCAD command through the application automation boundary. The template extraction tooling uses it to open DWG files before reading model space.
- `Acad.get_available()` and `sacad.env.available_acad()` discover installed supported AutoCAD versions.
- `Acad.name` exposes the resolved version identifier, and `Acad.com` provides the underlying application automation wrapper for advanced integration.

## Database operations

Sacad batches database work in operation objects. Creating an operation does not modify AutoCAD; `submit()` serializes and executes the complete request.

### Insert and update

`cad.db_insert(...)` creates a `DBInsert` operation.

- Insert at an explicit `Vector3d` origin with `insertion_point`.
- Ask the user for an origin with `prompt_insertion_point=True`.
- Control named-record replacement with `upsert`.
- Control the post-operation view with `ZoomMode.NONE`, `ZoomMode.ADDED`, or `ZoomMode.ALL`, plus an optional `zoom_factor`.
- Add one object with `insert()`, add an iterable with `insert_many()`, or use `insert_and_ref()` to assign a temporary object identity that another object such as a `Group` can reference in the same request.
- Populate model space, the block table, dimension-style table, layer table, linetype table, and text-style table through dedicated insertion proxies.
- Use `replace_db(database)` to submit a complete prepared `Database`, including resources and model-space entities, in one operation.

```python
import sacad as ac

with ac.instant_acad() as cad:
    operation = cad.db_insert(
        prompt_insertion_point=True,
        zoom_mode=ac.ZoomMode.ADDED,
        zoom_factor=1.25,
    )
    operation.layer_table.insert(
        ac.LayerTableRecord(
            name="STRUCTURE",
            color=ac.Color.index(3, ac.ColorMethod.BY_ACI),
        )
    )
    operation.model_space.insert_many([
        ac.Line.new(0, 0, 1200, 0, layer="STRUCTURE"),
        ac.Circle.new(600, 0, 75, layer="STRUCTURE"),
    ])
    cad.activate()
    result = operation.submit()
```

### Select and inspect

Selection operations return a `DBSelectResult` whose `db` contains the requested records and entities.

- `db_get_user_selection(by_prompt=False)` reads the pick-first selection; `by_prompt=True` opens an AutoCAD selection prompt and waits for confirmation.
- `db_get_tables(flags, ...)` retrieves any combination of model space, text styles, linetypes, layers, dimension styles, multileader styles, and blocks through `TableFlags`.
- `block_names` filters block-table retrieval. In the current managed implementation, pass a non-empty list of exact names; an empty list or `None` returns no block definitions.
- `explode_blocks=True` explodes block references while extracting entities from model space or a user selection.
- `db_get_groups(name_or_names)` retrieves named groups and their associated drawing content.
- `db_test_entities(...)` sends candidate entities to AutoCAD for evaluation. This is useful when AutoCAD-computed properties, such as geometric extents, are required before final insertion.

### Delete

`cad.db_delete(...)` creates a deletion operation.

- Put entities carrying AutoCAD object IDs in `operation.query.database` to delete those objects.
- Call `delete_group(name_or_names)` to delete named groups.
- Set `delete_group_entities=True` to remove both a group and the entities referenced by that group.
- `cancel()` is available on database operation objects to cancel the active request.

### Operation results

- `DBInsertResult` reports inserted, updated, and failed object counts and returns the user-selected insertion point when one was prompted.
- `DBSelectResult` carries the returned `Database`.
- `DBDeleteResult` reports the number of deleted objects.
- Every result has a `Status` (`UNKNOWN`, `SUCCESS`, `FAILURE`, or `WARNING`) and an optional message.
- Connection, COM, TCP, unsupported-version, and serialization failures use Sacad-specific exception types.

## Geometry and transformations

Sacad geometry objects are serializable and can be used independently of a live AutoCAD session.

### Vectors

`Vector2d` and `Vector3d` provide:

- Component access through `x`, `y`, and, for 3D vectors, `z`.
- Addition, subtraction, negation, scalar multiplication, and scalar division.
- Dot product by multiplying two vectors of the same dimension.
- A 2D scalar cross product or 3D vector cross product with the `@` operator.
- Magnitude through `abs(vector)` and unit vectors through `normalize()`.
- Standard axes through `xaxis()`, `yaxis()`, and `zaxis()`.
- Rotation in degrees with `rotate()` or radians with `rotater()`.
- Homogeneous transformation with `transform_by(matrix)`.

### Matrices

`Matrix3d` is a NumPy-backed 4-by-4 homogeneous transformation matrix.

- Start a transformation chain with `Matrix3d.identity()`.
- Translate with `move(...)`.
- Rotate in degrees with `rotate(...)` or radians with `rotater(...)`, around a principal or arbitrary 3D axis.
- Uniformly scale with `scale(...)` and independently request mirroring across the X, Y, or Z direction.
- Apply a matrix to an entity with `Entity.transform_by(matrix)`. Sacad stores the composed matrix with the entity for execution in AutoCAD.

## Drawing entities

Unless noted otherwise, these entity classes are available in the current Sacad Python source. The convenience constructors named `new()` and `new_vec2()` reduce the conversion required for common 2D drafting.

### Shared entity properties

Every `Entity` can carry a true color, AutoCAD color index, layer, linetype, linetype scale, lineweight, visibility, transformation matrix, and AutoCAD-computed `geometric_extents`. Entities inherit `clone()` from `DBObject` for deep-copying a complete serializable object graph.

### Curves and filled geometry

| Entity | Supported data |
| --- | --- |
| `Line` | 2D or 3D endpoints, normal, and thickness. |
| `Arc` | Center, radius, start/end angle, normal, and thickness. |
| `Circle` | Center, radius, normal, and thickness; diameter and circumference helpers are included. |
| `Ellipse` | Center, major/minor axes, and start/end angle. |
| `Polyline` | Lightweight 2D vertices, closed state, constant width, elevation, normal, and thickness. |
| `Vertex` | 2D point, bulge, start width, and end width for polyline segments. |
| `Solid` | A list of 3D corner points for filled 2D solids. |

### Text and annotation

| Entity | Supported data |
| --- | --- |
| `DBText` | Position/alignment point, text, height, text style, horizontal/vertical mode, attachment/justification, rotation, width factor, oblique angle, mirroring, normal, and thickness. |
| `MText` | Contents, location, attachment, text height, text style, width, and line-spacing factor. |
| `MLeader` | One or more leader-line point lists, content type, multileader style, embedded `MText`, and text alignment. |
| `Shape` | SHX style/name reference, position, size, rotation, width factor, oblique angle, normal, and thickness. |

### Hatches

`Hatch` supports associativity, hatch or gradient object type, normal/outer/ignore hatch styles, pattern name/type/angle/scale/doubling, and multiple `HatchLoop` boundaries. A loop may be expressed as a polyline or as a list of curves and classified with the `HatchLoopTypes` flags.

### Blocks

`BlockTableRecord` contains a named entity list and can be used both for actual named block definitions and as a convenient serializable envelope for a subdrawing. `BlockReference` supports the referenced block name, insertion position, rotation, and X/Y/Z scale factors.

### Dimensions

The base `Dimension` model exposes text placement and rotation, prefixes and suffixes, measurement output, dimension-style name, per-entity `DimStyleTableRecord` overrides, center-mark behavior, line spacing, and zero-suppression options. The following dimension entities are implemented:

- `AlignedDimension`.
- `RotatedDimension`.
- `RadialDimension`.
- `ArcDimension`.
- `DiametricDimension`.
- `LineAngularDimension2`.
- `Point3AngularDimension`.
- `RadialDimensionLarge`, including jogged-radius geometry.

## Colors, styles, blocks, and groups

### Colors

`Color.rgb(r, g, b)` creates a true-color value. `Color.index(i, method=...)` creates an indexed or method-based value. `ColorMethod` includes by-layer, by-block, by-ACI, true-color, foreground, pen, frozen/off-layer, and no-color modes.

### Drawing resources

The `Database` object contains:

- `block_table` with `BlockTableRecord` values.
- `dim_style_table` with `DimStyleTableRecord` values. The model exposes a broad set of AutoCAD DIM variables for unit formatting, precision, tolerances, text, arrows, lines, scaling, and suppression behavior.
- `layer_table` with `LayerTableRecord` values for color, on/off, frozen, locked, plottable, lineweight, and linetype state.
- `linetype_table` with `LinetypeTableRecord` values and `LinetypeSegment` definitions, including dash lengths and embedded shape/text configuration.
- `text_style_table` with `TextStyleTableRecord` values for font descriptors, SHX/big-font files, shape-file mode, vertical mode, oblique angle, size, and X scale.
- `m_leader_style_dict` with `MLeaderStyle` values for arrow, landing, dogleg, content, text style, alignment, angle, and attachment settings.
- `group_dict` with `Group` values containing a name, entity IDs, and selectable state.

`Database.get_block(name)` returns an existing block record or creates an empty named record. `ac.MODEL_SPACE` is the standard key used for model-space entities.

Multileader styles are supported by Sacad's database model and table-selection flags.

## JSON serialization and application data models

`Jsonify` is the common base for Sacad database objects, geometry, queries, and results, and it can also be inherited by custom classes.

- `serialize(**json_options)` and `deserialize(json_data)` convert complete polymorphic object graphs to and from JSON text.
- `to_jsonify_dict()` and `from_jsonify_dict(data)` perform the same conversion through JSON-compatible dictionaries, which is convenient for HTTP request and response bodies.
- Nested `Jsonify` objects, dictionaries, lists, tuples, sets, dataclass-like objects, and `IntEnum` values are traversed recursively. Attributes whose value is `None` are omitted.
- Serialized objects carry their full Python module and class name. During reconstruction, Sacad dynamically imports the defining module and instantiates the registered class.
- `register_excluded_attribute(name)` can ignore named fields during construction, helping consumers tolerate selected serialized attributes that should not be restored.
- `Jsonify.Encoder` integrates Sacad objects with `json.dumps(..., cls=Jsonify.Encoder)`.

The full-class-name mechanism is important when data crosses environment boundaries: every non-Sacad type present in a payload must be installed and importable in the environment that reconstructs it. A payload composed only of Sacad types requires only Sacad. Data containing custom types should be reconstructed only where those types are available.

```python
from dataclasses import dataclass
import sacad as ac


@dataclass
class DrawingPlacement(ac.Jsonify):
    name: str
    origin: ac.Vector2d = ac.Vector2d()


saved = DrawingPlacement("elevation", ac.Vector2d(120, 80)).serialize()
restored = DrawingPlacement.deserialize(saved)
```

## Architecture and performance model

- Python builds a complete operation request in memory.
- Sacad serializes the request over a local TCP bridge.
- A managed C# plug-in executes database-sensitive work through ObjectARX managed APIs inside AutoCAD.
- ActiveX automation starts or activates AutoCAD, loads the managed assembly, and dispatches commands at the application boundary.
- Returning selection data, styles, blocks, extents, and operation counts uses the same polymorphic object model.

This design is intended to replace many fine-grained automation calls with fewer coarse-grained database transactions. Actual performance depends on drawing size, entity mix, AutoCAD version, and how much work is grouped into each submission.

## Compatibility and current scope

- Sacad is Windows-specific: the current implementation uses AutoCAD, COM/`pywin32`, the Windows registry, and a managed ObjectARX assembly.
- The package currently reports version `0.0.1` in `sacad.__version__`.
- The Python package declares `pywin32==305` and NumPy as runtime dependencies.
- The current source defines AutoCAD version identifiers and registry mappings for AutoCAD 2010 through 2023, plus `ACAD_LATEST`. A version must also have a compatible built `SacadMgd.dll` available to be usable.
- Model space is implemented. Paper-space support is not exposed in the current Python source.
- Lightweight `Polyline` is implemented. `Polyline2d`, `Polyline3d`, `Ray`, `Spline`, and `Xline` are present only as commented placeholders in the current Python model and should not be treated as supported features.
- Sacad models and transfers drawing database objects; it is not a standalone DWG writer and still requires AutoCAD for database execution.
- `submit()` is synchronous. GUI applications should keep blocking submissions away from the UI thread and may use `cancel()` when their execution model permits cancellation.
- Prompted selection and prompted insertion are interactive AutoCAD operations. Activate AutoCAD before submission so the user can see and answer the prompt.
- Calling `open(netload=True)` may clear AutoCAD's current implied selection because it invokes `NETLOAD`. Use `netload=False` only when the managed module is already loaded and preserving the pick-first selection is required.

## Documentation scope

This inventory describes the features exposed by Sacad's current Python modules and bundled examples. It does not claim support for APIs that appear only as placeholders or commented declarations in the source.
